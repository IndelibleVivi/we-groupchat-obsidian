============================================
    we-groupchat-obsidian - 快速使用说明
============================================

这是随源码和本地 .app bundle 保留的离线快速入门，不是完整手册。
当前公开说明、隐私边界和所有 operator 命令以 README.zh-CN.md 为准：

  https://github.com/IndelibleVivi/we-groupchat-obsidian/blob/main/README.zh-CN.md

这个项目是 source-distributed macOS menu-bar app。公开 repo 是正式分发入口；
目前不提供已签名 installer、.dmg 或 bundled Python runtime。


============================================
    第一次运行
============================================

1. 从公开 repo clone：

     git clone https://github.com/IndelibleVivi/we-groupchat-obsidian.git
     cd we-groupchat-obsidian
     ./启动.command

2. 首次运行或 requirements.txt 变化时，启动脚本会先询问是否创建/更新
   当前 checkout 自己的 .venv 并安装 dependencies。只有输入 y 才继续；
   拒绝就退出，不会静默安装。

3. 如果 macOS 拦截 .command：

   - 在 Finder 里右键「启动.command」并选择“打开”；或
   - 到“系统设置 -> 隐私与安全性”确认“仍要打开”。

4. 菜单栏出现 💬 图标后，在“设置”里选择 AI provider 并填写 API Key。

支持通义千问（新安装默认）、DeepSeek、Claude、OpenAI、Ollama 和自定义
OpenAI-compatible endpoint。API Key 存在 macOS Keychain，不写入 repo。
云端 provider 会收到你要求总结/判断的聊天文本；需要本地 AI 时使用 Ollama。

macOS 可能在菜单 app 启动后询问一次 WeChat App Data 访问。source guard、
monitor 与 mounted-resource timer 都由这只长驻 app 负责，不会靠每几分钟启动
短命 worker 来反复索取授权。附件 bytes 解析还需要单独开启，授权只在当前
app process/session 内存里有效，重启后自动关闭。

普通启动不会偷偷 re-sign WeChat。只有健康检查确认需要、并且你接受终端里
说明的影响时，才显式运行：

     ./启动.command --allow-wechat-resign

这一步可能退出微信并请求 Mac 登录密码。sudo 输入密码时不显示字符或星号是正常的。


============================================
    日常入口
============================================

启动菜单栏 app：

     ./启动.command

前台启动时关闭该 Terminal 或按 Ctrl+C 会结束这次 app process。需要登录自启时，
请使用下面的安装入口；不要自己复制或改写 LaunchAgent plist。

常用 Finder/Terminal helper：

     ./launchers/配置关注推送.command
     ./launchers/健康检查.command
     ./launchers/刷新数据源.command
     ./launchers/历史总结到Obsidian.command
     ./launchers/整理Obsidian输出.command
     ./launchers/补跑遗漏笔记.command
     ./launchers/安装自动启动.command
     ./launchers/卸载自动启动.command

“补跑遗漏笔记”默认只 audit。加 --apply 后，它会先停 managed LaunchAgent，再获取
menu app 的同一把 singleton lock；如果显示 menu_app_active，不会写 monitor state、
SQLite 或 Obsidian projection。不要同时开着手动 menu app 强行补跑，也不要手改
monitor state JSON；corrupt/symlink state 会 fail closed，不会自动跳到 now。

微信更新后先跑“健康检查”，只有它提示 DB key / re-sign / missing shard 问题时，
再运行“刷新数据源”。普通健康检查默认 redacted；只有本机私下排查才考虑
加 --sensitive。

macOS WeChat 4.1.11 (269136, arm64) 已有精确 build profile：刷新程序只读扫描
WeChat task memory 中受保护的 cipher context，按该 build 的 profile 解码候选 key，
并用对应数据库第一页的 HMAC 逐一验证后才写入本机 private key cache。缓存按
验证结果累计更新，不会因为一次 partial/empty scan 丢掉先前已验证的 key。
未知的后续 WeChat build 会 fail closed 并保留旧缓存；不要手工复制猜测的 mask/key。
如果本机 WeChat 需要 ad-hoc re-sign，只有显式允许的刷新流程才会执行，并且仅在
它确实关闭了 WeChat 时重新打开 app。


============================================
    主要数据位置
============================================

配置、运行状态、普通总结 .txt、SQLite ledger、日志和默认 Markdown：

     ~/.we-groupchat-obsidian/

旧 ~/.wechat-summary/ 只作为本机 migration/compatibility 路径保留。
如果配置了 Obsidian vault，Markdown projection 会写入你选择的 vault 子目录。

附件 archive、backup manifest、mounted target receipt、OAuth client JSON、聊天
数据库/key、日志和真实 Markdown vault 都是 private runtime data；不要提交或转发。
附件 archive 默认关闭。开启后，resolved bytes 进入本机 SHA-256 content-addressed
archive；Obsidian note 可以链接到私有归档 object，但附件 bytes 不会被复制进 vault。


============================================
    功能与安全边界
============================================

- 群聊总结、按天回顾、批量总结和关键词搜索。
- 关注推送、SQLite knowledge ledger、Obsidian Markdown、Daily Digest 和
  actionable Review Queue。
- 可选 source guard、本地附件 CAS、filesystem snapshot、selected-resource
  mounted backup，以及独立 opt-in 的 Google Drive API advanced lane。
- 默认关闭远程 URL preview、附件 bytes 解析、archive、resource backup 和
  source guard；MCP 真实发送已经退休，不存在可重新启用的 mode。
- Mounted target 只证明目标 filesystem bytes/readback，不证明云端 provider 已上传。
- 每轮 mounted backup 会维护 wgo-resource-backup/00-打开微信资源备份.md；也可从菜单
  “在 Finder 打开文件备份”直接进入。入口分成“文件备份”“待补齐附件”“资源索引”：
  文件备份只列真正已交付的去重文件，并显示群聊出现次数；待补齐页按真实状态分组且没有
  target link。看到“本地缓存暂未找到”时，先在微信里重新打开或下载附件，再点立即更新。
  “已备份”只表示 mounted target 已交付并即时校验，不表示 provider 云端同步已经完成。
- 历史 resource backfill 先生成 bounded plan，再用同一个未过期 run_id apply；
  不会在确认后重新无限 rescan。
- MCP 是可选 legacy read-only compatibility surface；读取会把本机
  chat-derived data 暴露给 MCP client，AI summary 还会进入用户配置的 provider。
  它不推进 bookmark、不改分组，也不能发送微信消息。旧 send tool 只返回
  mcp_send_retired。

更完整的能力索引见 功能说明.txt；准确的 architecture、commands 和 privacy contract
仍请以 README.zh-CN.md、docs/source-reliability.zh-CN.md 和
docs/resource-capture-and-mounted-backup-spec.md 为准。


============================================
    更新与分享
============================================

公开 repo 是正常更新和分享方式：

     git pull --ff-only
     ./启动.command

分享给别人时只发送公开 repo 或中文版 README 链接：

     https://github.com/IndelibleVivi/we-groupchat-obsidian
     https://github.com/IndelibleVivi/we-groupchat-obsidian/blob/main/README.zh-CN.md

不要压缩已经运行过的 checkout；它可能包含 .venv、runtime state、cache、日志或
私有调试材料。scripts/build_share_package.py 只保留为无 Git/网络环境和 exact-commit
归档所需的历史 offline fallback，不是群友分发主路。
