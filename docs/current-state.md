# Current source state

This checkout contains the semantic-generation rebuild candidate on top of the
October Ops source line. Package metadata remains `v0.1.0-alpha.1`; no new release
is implied by this document.

The [development programme](development-programme.md) records the mature product
goal and continuous construction order. The source now connects daily View induction,
explicit View controls and known-version change pages to the reader. Current gaps
include evidence synthesis beyond query hit excerpts, large-catalog navigation,
automatic removal/reclassification of old memberships, and real reading acceptance.
Structural tests do not establish real
editorial quality or native reading acceptance.

Live View v2 uses metadata pages of at most 16 Items, one page per reader turn.
Complete View context is bounded at 60 KB; oversized context stops explicitly.
Accepted TEXT/CHOICE artifacts precede a short fresh-CAS canonical transaction;
program jobs, membership changes and receipts commit together. Idle/deferred
unchanged scopes make no new calls; unknown work blocks new contexts. Frozen
rebuild v1 remains unchanged, including historical stale-action limitations.
`主题管理.md` registers explicit definition and existing-member pin/exclude intent;
View changes and action consumption share a transaction. Automated induction adds
memberships and does not delete old ones when a definition changes.
`变化.md` and per-Item pages compare current canonical snapshots with explicit
known revisions, preserving opened/known independence, conflict guards and identity
renames. They add no model calls. Their previews and selection are bounded and
disclose omitted material. Source support is separate from installed/live acceptance.

Active semantic health now observes local reader delivery status counts without
opening event payloads or initializing tables. Unknown/sending receipts prevent
`healthy`; deferred delivery remains `pending`. Historical rejection is visible
without imposing a permanent generation-wide gate, and accepted/silent never
means read or known. Inactive candidates retain unprobed delivery status.

The source candidate adds shared source-free derived maintenance for app reader
turns and monitor downstream. Index and projection attempts have separate results;
local object publication failures retain their work while independent targets
continue. Reader status exposes current maintenance counts/codes. Strict rebuild
publication remains separate from best-effort maintenance and requires actual
Item/View/control/home completion.
`ReadingHome` publishes `WGO/首页.md` from bounded metadata, linking ready Items,
views, today's latest successful brief and controls. It displays current,
visible-open and explicit known versions independently, including new versions
after an earlier open. The menu opens the identity-resolved home on a daemon
without model providers. Long labels and unsupported filename delimiters have
explicit safe display fallbacks. This is source support, not installation,
private-generation repair or native reading acceptance.

  has resumed or completed.

  `repetition_truncation` as known truncation in streaming and non-streaming

  rename checks without decoding unrelated note bodies into whole strings.
  During one source-first history publication, stable POSIX fd/path metadata

  Supported POSIX history scans use directory-relative no-follow file opens

Run-journal storage now uses compact v2 metadata and immutable private payloads.
The locked `compact-journal` command upgrades interrupted inline v1 runs without
starting source/model processing; original bytes remain available for recovery.
This is source capability, not evidence that any private run has been converted

An empty, pre-capture/pre-provider candidate can renew its plan expiry at the
same root through `renew-plan`. Apply needs the explicit runtime grant, exact
config/root binding, no active/cutover/finalized state, and both owner locks.
Only expiry changes; old compact plans and append-only renewal receipts remain.
Resume still requires source/model grants and a fresh freeze. Repeated exact
inventory refs share one history publication within a call while every freeze's
independent whole-DB backup is checked; later calls repair projections again.
These are source capabilities, not private-run or activation claims.

An unpinned, pre-activation run whose runtime root moved can
be relocated to another already-mounted private local root by the explicit
`relocate` recovery. It copies run/generation state (SQLite via Online Backup
including WAL), rebinds only the operational plan, adopts `semantic_runtime_root`
through the locked ConfigStore patch and leaves a retirement record for the
retained original root, preserving the run/generation, raw captures, jobs and
immutable evidence. It never fabricates a missing destination root and admits a
changed TEXT/DECISION binding only while the generation has zero jobs. This is
source capability, not evidence that any private run was relocated.
An explicitly configured unavailable runtime root blocks app, monitor, health
and legacy dispatch with `semantic_runtime_root_unavailable`; it is not treated
as an unmigrated installation. Relocation verification streams copied files,
and SQLite retries publish a fresh WAL-aware Online Backup atomically.

Local cosine now keeps vectors in a private disposable SQLite disk cache, and
retrieval reads bounded vector payload pages instead of retaining all vectors
and receipt payloads in Python. This candidate change does not establish a
whole-migration RAM bound or real private-data acceptance.
Full-rebuild extraction preparation also releases each durable artifact rather
than collecting every batch's observations in the scheduler's result list.
Resolution reads the accepted result for one batch at a time.

Independent verification now uses a private temporary disk snapshot and scoped
SQL reads instead of an in-memory database and whole-corpus payload dictionaries.
Computed vectors and receipt anchors use disposable disk scratch. This preserves
complete checks and WAL consistency; caller manifest metadata, identity sets and
the largest individual record still contribute memory. Temporary disk capacity
and full private-run acceptance remain separate operational requirements.
