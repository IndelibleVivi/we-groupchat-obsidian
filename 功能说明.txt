============================================

这份 .txt 方便在 Finder 或离线源码里快速浏览当前能力，不承担完整 contract。
用户与 operator authority 是 README.zh-CN.md；可靠性和资源流的 formal contract 是：

============================================
    一、菜单栏总结与搜索
============================================

- 总结新消息：从每个群聊已提交的 bookmark 继续读取，不重复消费已成功总结的窗口。
- 自定义总结：按最近 N 条或最近 N 分钟回顾，不改变普通增量总结的选择方式。
- 按天总结：选择某一天生成独立 .txt summary。
- 分组与批量总结：按本地分组汇总多个群聊的新消息。
- 关键词搜索：按日期和 chat scope 检索，可直接查看原文或交给 AI 归纳。
- 最近总结：在菜单里预览、复制、打开 summary；普通 summary .txt 默认保存在
  ~/.we-groupchat-obsidian/。


============================================
    二、关注推送与 Obsidian knowledge workflow
============================================

Topic monitor 负责把“值得以后再找”的群聊窗口写入本地 durable knowledge ledger，
而不是把每条消息都弹成通知：

- monitor_knowledge.db 是 topics、events、relations、FTS、attachment mentions 的
  canonical derived state。
- Markdown note、00-按日期.md、Daily Digest 和 resource indexes 是可重建 projection。
- 普通、[链接]、[文件]、[链接+文件] note 使用不同标题标记和 resource metadata。
- P1/P2/P3 决定通知强度；关闭“后台通知”只静音自动 banner，不停止 monitor、
  SQLite commit、Obsidian projection 或 Daily Digest。
- Daily Digest 汇总已保存的知识 note；Review Queue 只保留 follow_up_resource、
  import_resource、evaluate_reference、review_risk 等有具体下一步的条目。
- Resource Lead 能保留“可以私发 / 晚点发 / repo 还没公开 / 求一份”但资源尚未
  出现的窗口，避免只看当前有没有 URL/file。
- Remote link preview 默认关闭；开启后远端网站会收到请求 metadata。

Knowledge event 与 attachment mention 在同一个 SQLite transaction 里提交。
随后 attachment resolution 或 Markdown projection 失败，不会回滚 event，也不会把
monitor checkpoint 倒退成“没处理过”。


============================================
    三、附件 catalog 与本地 archive
============================================

- Attachment catalog 记录稳定 source occurrence、文件 metadata 与 resolution state。
- 读取 attachment bytes 需要当前 app process/session 的显式 consent；不会写进 config，
  重启后必定归零。关闭授权后，in-flight resolver 会在下一次 byte operation 前取消。
- Archive 默认关闭。开启后，resolved bytes 进入私有 SHA-256 content-addressed store；
  相同 bytes 只保存一份，catalog occurrence 仍各自保留。
- File 默认可 opt-in；image 是独立 opt-in，不能被 file consent 顺带开启。
- Destructive partial recovery、临时文件清理和 occurrence claim 都发生在 archive
  process lock 内；ready_local 不会被较晚失败的 resolver 倒写成失败。
- Knowledge note 可以记录 archive status，并在成功归档后提供本机 CAS object link；
  vault 自身不复制 attachment bytes。


============================================
    四、资源 capture、backfill 与 mounted backup
============================================

默认 selected-resource lane 不需要 OAuth：

- 实际 capture scope 是 active monitor chats 与 resource backup 独立 selection 的交集。
- Scan/backfill/apply 在 capture lock 内重读 canonical selection/config；选群变更后，
  stale snapshot 不能继续扫描或提交已取消选择的 chat。
- Link/file occurrence 先提交 SQLite；文件只有 ready_local 才能进入 target handoff。
- 历史补链先写 bounded keyset pages 和 run_id；apply 只接受 exact、未过期 run_id，
  不会 confirm 后重新 rescan。
- Projection 以 real output root 为跨数据库 ownership boundary，manifest 绑定 archive_id；
  busy、unknown、nested failure 都 fail closed。
- Mounted target 可以是 Google Drive for Desktop、Dropbox、iCloud Drive 或普通目录。
  sync_delegated 只证明目标 bytes/readback，不证明 provider-side upload。
- 输出包括 immutable CAS object、privacy-bounded catalog snapshot、Markdown resource
  indexes 和 receipts；GC 只删除 manifest-owned generated paths。
- Mounted 根部的 00-打开微信资源备份.md 是人类入口；菜单也可以直接在 Finder reveal。
  入口下有文件备份、待补齐附件和资源总索引三套平行 view。文件备份按群聊/月列已交付
  digest，每个 object 一行并显示 occurrence 次数；待补齐页按 queued、cache unavailable、retry、
  local-space、attention、awaiting-handoff 与 unknown 分组，不生成 target link。三套 view 共用
  同一个 coverage classifier，且不复制第二份 bytes。

另有两个独立 advanced lane：

- Filesystem snapshot：对整个私有 attachment archive 做 plan/run/verify/read-only
  restore plan。
- Direct Google Drive API sync：独立 selection、OAuth、durable queue、per-chat/month
  shortcuts 和 retry/reconcile；不与默认 mounted backup 共用“成功”语义，也不自动删除。


============================================
    五、WeChat source reliability
============================================

- WeChat encrypted database 是 raw source authority；项目读取本地 source 并维护自己的
  decrypted snapshot/cache，不回写微信聊天数据库。
- Plaintext SQLite snapshot 使用 Online Backup，避免忽略 WAL 中已提交的数据。
- macOS WeChat 4.1.11 (269136, arm64) 使用 exact build profile 只读扫描受保护的
  cipher context；候选 key 必须通过目标数据库第一页 HMAC 验证，才会累计、原子地
  发布到 private key cache。partial/empty/unsupported scan 保留先前已验证缓存并
  fail closed，不持久化 raw candidates。
- Source shards、message identity、cursor 和 attachment occurrence 都按 source root
  namespace，避免不同账号/数据根互相碰撞。
- 可选 source guard 运行在长驻菜单 app 内，受 grace、pause、restart budget、
  exponential backoff 和 content-free receipts 约束。
- Source guard 只请求 macOS 正常打开微信；不会 kill、re-sign、登录或操作微信 UI，
  也不会把 process lookup unknown 猜成“微信没运行”。


============================================
    六、MCP Server
============================================

MCP 可以让 Claude Desktop、Claude Code、Cursor、OpenClaw 等 client 查询 chat list、
读取消息、搜索、总结和查看图片。Read tools 会把本机 chat-derived data 暴露给 client。

它是可选 legacy read-only compatibility surface：summary 不推进 bookmark；
manage_chat_groups 只允许 list；旧 mutation actions 返回 mcp_mutation_retired。
MCP 真实发送已经退休。prepare_send_message、confirm_send_message 与 send_message
暂时保留旧 tool name，但始终只返回 mcp_send_retired，不读 config、不 import sender、
不触碰微信 UI。旧 send config keys 完全 inert。


============================================
    七、运行 ownership 与维护入口
============================================

- ConfigStore 是 main config 的唯一 writer；每次写入都在 lock 内 patch latest revision。
- 长驻 menu app 是 monitor、source guard 与 mounted-resource timer 的 runtime owner。
- MonitorStateStore 是 per-chat checkpoint 的唯一 writer：valid legacy state 在成功 parse 后
  才迁移；corrupt/symlink/non-regular fail closed；revision CAS 阻止 stale overwrite；AI
  failure 不改 canonical state。
- 补跑写入会在停 managed LaunchAgent 后再拿 menu app 同一把 AppInstanceLock，并持有到
  backup、drain、projection、validation 与 receipt 全部结束；release 后才恢复 LaunchAgent。
  `menu_app_active` 不做 canonical writes。
- Retired short-lived source/resource LaunchAgent 只保留 inspect/uninstall cleanup，不能重装。
- 所有 capture、backfill、archive、projection、handoff 都必须使用自己的 cross-process
  ownership locks；worker_busy 或 unknown 不是 success。

常用入口：

  ./启动.command
  ./launchers/配置关注推送.command
  ./launchers/健康检查.command
  ./launchers/刷新数据源.command
  ./launchers/历史总结到Obsidian.command
  ./launchers/整理Obsidian输出.command
  ./launchers/补跑遗漏笔记.command
  ./launchers/安装自动启动.command
  ./launchers/卸载自动启动.command

完整 resource/archive/source guard CLI 和 safe rollout 顺序请看
README.zh-CN.md 与 docs/source-reliability.zh-CN.md；不要用这份索引替代操作前置条件。
